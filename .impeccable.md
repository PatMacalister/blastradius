# Design Context — BlastRadius

## Target audience

Developers running AI coding agents — Cursor, Claude Code, Copilot Workspace, agentic CI —
against real infrastructure. Mostly solo founders, small teams, and platform engineers at
companies too small to have a security function.

Critically: **this audience is saturated with security marketing and has learned to distrust
it.** They can smell a scare-ware funnel instantly, and the reflex is to close the tab. They
will judge whether the tool is real by whether the page sounds like it was written by someone
who has read an API's permissions documentation, not by someone selling.

They also mostly do not believe this applies to them. The token in question was created for
something innocuous, months ago, by them.

## Use cases

1. "An agent is running on my laptop with my credentials. What can it actually reach?"
2. "I'm about to let an agent touch production. What's the worst case if it misfires?"
3. "We just onboarded an MCP server that wanted an API key. What did we just hand it?"

The dominant job is **making an invisible risk legible**. Not creating fear — the reader
usually has no fear at all — but converting "I have some tokens around" into a specific,
ranked, finite list of things one process can destroy.

## Brand personality / tone

**Clinical, precise, and unwilling to overclaim.** BlastRadius is an instrument. Its entire
credibility rests on the fact that it says "I could not determine this" out loud instead of
producing a tidier answer.

- **Never alarmist.** The material is inherently dramatic — a nine-second unrecoverable
  deletion — which is exactly why the delivery must be flat. Let the facts carry it. Any
  amplification reads as manipulation and forfeits the audience.
- **Never overclaim coverage.** The page must state what the tool cannot do: no AWS, no scope
  resolution on Cloudflare, six providers only. A security tool that hides its gaps is lying,
  and this one is architecturally built around admitting them.
- **Consequence language, never scope language.** "Can delete your production volume", not
  "has `volumes:write`". This is enforced in the code and must hold on the page.
- **No shaming.** The reference incident is told as a mechanism, in the abstract. The company
  it happened to is named once, in `INCIDENTS.md`, as a citation. The founder published the
  details so others could learn; using them as a cautionary brand would be a poor return.

## Aesthetic direction

**Incident noir** — a fault sequence from an accident report, read at night.

The page opens on nine seconds, rendered as a timeline. Not a re-enactment of anyone's
outage: a *mechanism*, the way an aviation report diagrams a chain of events rather than
dramatising a crash. Each second is a line in a ledger. At the moment the credential is
picked up there is an intervention point — where the tool would have spoken. The pitch is
delivered structurally, by the shape of the page, rather than by a headline making a claim.

- **Ground**: deep ink-blue-black, never pure black. Bone-white text, never pure white.
- **One accent**: ember/vermilion, used *only* where something is genuinely destroyed.
  Severity colours are lifted from the CLI's own output so the page and the tool agree.
- **Type**: Instrument Serif for statements (high contrast, editorial, dramatic without
  volume), Archivo for body, JetBrains Mono for anything that is literally terminal output.
  All self-hosted, all OFL.
- **Structure**: a hairline timeline gutter running down the left, content offset asymmetric
  against it. Rules and indentation instead of cards.

### Explicitly not

- **No glow, no neon, no scanlines.** Dark is not an excuse for a cyberpunk dashboard. This
  is a printed report under a desk lamp. If it looks like a hacker movie, it has failed.
- No cards, no card grids, no icon-above-heading rows.
- No gradient text, no glassmorphism, no drop shadows as decoration.
- No fake dashboard screenshots. Every line of terminal output on this page is generated by
  the tool's actual renderer.

## Non-negotiable

**Nothing on this page may claim something the tool cannot currently do.** The install command
does not work yet — not published to npm, repo private — so the page is built complete and
**held from deployment** until launch. The single block that becomes true at publish is marked
`LAUNCH-GATE` in the HTML.

The tool's four refusals are the most persuasive content available and get their own section:
it never prints a raw secret, never sends a credential anywhere but its issuer, never reports
unknown as safe, and never claims a clean bill of health. A page for a tool built on admitting
limits should be the most honest page in the portfolio.
